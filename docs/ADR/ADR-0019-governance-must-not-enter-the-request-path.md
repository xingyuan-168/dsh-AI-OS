# ADR-0019：治理层不得进入模型请求的关键路径

## 状态

Accepted（补充 ADR-0018 的宿主集成设计；不改变三层强制模型与判定内核）。

## 上下文

治理插件通过 `ctx.tools.register` 注册了 8 个工具。实测暴露了一个设计缺陷：工具 schema 会进入**每一次模型请求**的工具目录，因此它属于**请求载荷**，不属于治理判定。

后果在一次真实故障中显现：`parameters` 传成"按键 DSL"后根节点没有 `type`，提供方返回

```
Invalid schema for function 'approval_record': schema must be a JSON Schema of
'type: "object"', got 'type: null'
```

并拒绝了**整轮请求**。也就是说，治理层的一个笔误让会话完全不可用，而不是让某个操作被拒绝。

这与治理层的既定语义直接冲突：治理只能回答"允许"或"不允许及为什么"。**"会话跑不起来"不是治理的合法输出，而是缺陷。**

此外还有一个此前未被点明的代价：8 个工具进入每个会话的请求（包括与治理无关的会话），扩大了工具面与注意力开销。

## 选项

- **A. 保持工具默认开启，仅靠测试防回归**：测试只能覆盖已知的坏形态；任何遗漏的代价都是"会话不可用"而非"一次拒绝"，代价与收益严重不对称。否决。
- **B. 删除工具面**：工具面本身有价值（代理可直接调用治理能力），且 MCP 与 CLI 已提供等价能力；为一次故障删掉整个面属过度反应。否决。
- **C. 默认关闭 + 注册前自校验 + 显式 opt-in**：默认不向模型暴露任何治理工具；需要时一行配置打开；无论开关状态，任何工具定义在注册前都必须自校验。选中。

## 决定

1. **`exposeTools` 默认 `false`**：默认配置下插件不向模型工具目录贡献任何条目。强制面（`tools/pre-execute`）与会话上下文（`agent/created` + prompt section）**永不依赖**该开关。
2. **注册前自校验**：`assertToolSchema()` 校验 `name`/`description`/`execute`/`parameters`（根 `type: "object"`、`properties` 为对象、`required` 为数组且其键都已声明）/`output.schema`/`output.render`。任一不通过 → **跳过该工具并大声记录（带工具名）**，绝不交给宿主；其余工具不受影响。
3. **模型可见面清单化**：凡进入模型可见范围的面必须显式登记其性质与失败后果——
   - 工具目录 = **每次请求**，schema 非法即整轮失败（本次缺陷所在）；
   - 技能目录 = **按需拉取**（模型调用 `skill` 时才取），失败后果局限于该次拉取；
   - 会话上下文 = **文本**，按设计注入，用于告知治理契约。
   新增任何模型可见面必须先说明它属于哪一类、失败时会发生什么。
4. **失败语义约束**：治理层对任一操作只能输出"允许"或"拒绝 + 规则编号"。任何使会话或请求不可用的行为都按缺陷处理，不作为可接受的降级。

## 后果

- **正面**：治理层默认对模型"零可见面"，一次 schema 笔误不再能让会话失败；每个请求的工具目录保持宿主原有规模；需要工具面的用户仍可一行打开。
- **负面**：默认情况下代理不能直接调用 8 个治理工具，需改用等价的 `aios` CLI（`check`/`finish`/`approval record`/`worktree`/`memory`/`context refresh` 均支持 `--json`）；Skills 已按"工具可用则用工具、否则用 CLI"表述。
- **成本**：多一层注册前自校验，开销可忽略。
- **复核条件**：若宿主提供"单个工具 schema 非法不影响其余请求"的隔离机制，或工具面可被隔离到独立请求通道，可重新评估默认值。
