# AI Engineering OS（AI-OS3）进一步完善修复计划

## 文档目的

本文档基于对当前 `AI-OS(3)` 源码版本的审计结果生成。

目标不是继续扩展 AIOS 能力，而是在当前正确方向上继续收敛：

> Codex 负责专业工程执行；AI Engineering OS 负责少量关键工程约束。

本轮重点：

-   修复治理边界漏洞；
-   清理旧架构残留；
-   强化关键规则不可绕过；
-   删除无价值复杂度；
-   保持 Codex 原生能力不受限制。

禁止重新引入：

-   Workflow Engine
-   Agent Scheduler
-   Evidence Runtime
-   Execution Runtime
-   OCI Runtime
-   复杂状态机
-   复杂审批系统

------------------------------------------------------------------------

# 一、当前版本总体评价

当前版本已经完成重要架构纠偏：

已正确：

-   AIOS定位为治理层；
-   不替代Codex；
-   不管理模型；
-   不实现Agent Runtime；
-   Worktree作为隔离工具；
-   Memory采用工程记忆；
-   SQLite作为索引而非事实源；
-   Gate数量收敛；
-   Authorization从角色权限转为行为权限。

当前评分：

约 8.5 / 10。

剩余问题主要集中：

1.  边界强制不够彻底；
2.  少量旧架构语义残留；
3.  部分规则仍可能被绕过；
4.  仓库卫生最后一公里；
5.  文档治理需要继续减重。

------------------------------------------------------------------------

# 二、P0 必须修复问题

------------------------------------------------------------------------

# P0-001 Code Start Gate 增强

## 问题

当前 Code Start 已接入 Hook，但是仍存在绕过可能。

目前主要依赖：

-   ApplyPatch；
-   Write/Edit；
-   工具路径判断。

风险：

Codex可能通过：

``` bash
echo xxx > src/a.py
```

或者：

``` bash
python generate.py
```

间接修改源码。

------------------------------------------------------------------------

## 修改目标

Code Start 必须形成双保险：

## 第一层

PreToolUse 阶段：

发现正式代码写入：

立即检查：

-   GitHub状态；
-   Research状态；
-   Governance状态。

失败直接 DENY。

------------------------------------------------------------------------

## 第二层

Finish阶段：

检查实际 Git diff。

如果：

-   新增源码；
-   修改正式代码；

但是没有对应 Code Start 记录或满足条件：

Finish失败。

------------------------------------------------------------------------

## 不要求

不要：

-   实时文件监控；
-   daemon；
-   sandbox；
-   execution runtime。

只需要：

入口拦截 + 完成检查。

------------------------------------------------------------------------

# P0-002 Research Gate 增强

## 当前问题

Research 已经比旧版本好。

但是仍可能：

一个旧研究文件：

``` markdown
Decision: build
```

长期解锁所有需求。

------------------------------------------------------------------------

## 修改要求

Research必须绑定：

-   requirement；
-   scope；
-   修改范围。

最低要求：

``` yaml
requirement_id:
scope:
decision:
reason:
updated_at:
```

例如：

``` yaml
requirement_id: REQ-MEMORY-001

scope:
  - memory

decision: extract

reason:
  existing project provides required capability
```

------------------------------------------------------------------------

## 验证规则

必须检查：

当前需求：

匹配

↓

当前Research:

匹配

↓

允许开发。

------------------------------------------------------------------------

## 禁止

不要新增：

-   Research数据库；
-   Candidate数据库；
-   评分系统；
-   AI自动判断系统。

------------------------------------------------------------------------

# P0-003 Frontend Approval 长期事实化

## 当前问题

Frontend Gate方向正确。

但是需要确认：

Approval不能只存在：

``` text
SQLite
```

因为：

换机器或者重新clone：

批准事实丢失。

------------------------------------------------------------------------

## 正确设计

事实源：

``` text
Git管理文档
```

例如：

``` text
docs/design/UI_SPEC.md
```

保存：

``` yaml
approval:
  type: frontend
  scope: dashboard
  status: approved
  approved_by:user
  approved_at:
```

SQLite：

只作为：

-   查询索引；
-   缓存。

------------------------------------------------------------------------

## 必须禁止

以下方式：

``` python
approved=True
```

直接通过。

Approval必须来自事实文件。

------------------------------------------------------------------------

# P0-004 Worktree Cleanup 安全修复

## 当前问题

方向正确：

finish != merged

但是必须确认：

cleanup不能只看状态。

------------------------------------------------------------------------

## 正确流程

``` text
active

↓

finish

↓

ready

↓

Codex/Git完成merge

↓

cleanup检查

↓

删除
```

------------------------------------------------------------------------

## Cleanup必须验证

Git：

``` text
branch commit
是否已经存在 target branch
```

例如：

使用：

``` bash
git merge-base --is-ancestor
```

逻辑。

------------------------------------------------------------------------

## 禁止

不能：

``` text
status=ready
直接删除
```

不能：

``` text
force=True
绕过保护
```

# P1-002 Authorization继续瘦身

目标：

Authorization只判断：

## 保留

-   用户资产保护；
-   input保护；
-   危险Git操作；

-   Agent角色；
-   backend-engineer；
-   frontend-engineer；
-   workflow权限。

------------------------------------------------------------------------

``` text

```


# 九、最终验收

完成后必须满足：

## Codex能力

-   正常编码不受影响；
-   正常测试不受影响；
-   正常安装依赖不受影响；
-   正常Git流程不受影响。

------------------------------------------------------------------------

## AIOS治理

必须真正保证：

-   没GitHub不能正式开发；
-   新需求必须查开源；
-   不允许v1/v2复制污染；
-   前端先确认；
-   Worktree安全隔离；
-   完成自动清垃圾；
-   Memory只保存工程经验。

------------------------------------------------------------------------

# 十、最终目标

不是打造另一个AI开发系统。

而是：

    Codex专业工程能力
              +
    AIOS工程纪律约束
              =
    稳定、高质量的软件研发流程

AIOS越小，边界越清晰，长期价值越高。
